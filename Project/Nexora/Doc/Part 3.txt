
related_name என்பதுதான் reverse accessor name.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
related_name இல்லாமல் இருந்தால்?

--- Django default name கொடுக்கும்:
--- ForeignKeyக்கு → <modelname>_set (எ.கா. cartitem_set)
--- OneToOneFieldக்கு → default model name (clash இருந்தா error வரும்)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
சுருக்கமாக:

--- Forward access = foreign key field name-ஐ பயன்படுத்துவோம் (item.cart).
--- Reverse access = related_name-ஐ பயன்படுத்துவோம் (cart.items).
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
சுருக்கமாக:

--- @property use பண்ணினால் → parantheses ( ) போடாமலே access செய்யலாம்.
--- இல்லேன்னா → method போல ( ) போட்டு call செய்யணும்.

@property ஏன் useful?

--- Readability → ஒரு cart-க்கு total price “ஒரு value” மாதிரி தான் இருக்கும்; function போல இல்லாம attribute மாதிரி access பண்ணினா natural-ஆ இருக்கும் (cart.total_price).
--- Django Templates → Django templates-ல் methods-ஐ call செய்ய முடியாது ({{ cart.total_price() }} வேலை செய்யாது). ஆனால் property-ஆ இருந்தா easy-ஆ {{ cart.total_price }} என்று பயன்படுத்தலாம்.
--- Encapsulation → உங்களுக்கு later calculation logic change பண்ணணும் என்றாலும் outside code எல்லாம் cart.total_price என்றே இருக்கும், safe-ஆ இருக்கிறது.

subtotal = serializers.SerializerMethodField()

👉 “subtotal details-ஐ database-ல column-ஆ save பண்ணாம, runtime-ல் (dynamic-ஆ) calculate பண்ணி, API response-க்கு மட்டும் சேர்க்குறோம்.”

🎯 சுருக்கம்:

--- DB-ல் இல்லை
--- Serializer response-ல மட்டும் வரும்
--- Dynamic calculation (எப்போ request பண்ணுறோமோ அப்போ calculate பண்ணும்)

1. Meta.fields என்ன செய்கிறது?

--- Serializer-க்கு என்ன fields API response/request-ல் வரணும் என்பதை control பண்ணுது.
--- இது model-ல் உள்ள fields மட்டும் அல்ல, serializer-ல் நம்ம define பண்ணிய extra fields-யும் சேர்க்க முடியும்.
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

🎯 சுருக்கம்:

--- obj = serializer process பண்ணுற current CartItem row.
--- Loop-ல பல items இருந்தா, ஒவ்வொரு item-க்கும் அந்த row தான் obj ஆக வரும்.

--- SerializerMethodField use பண்ணுவோம் → calculated / custom fields response-ல காட்ட.

அதாவது:

--- உங்க code-க்கு cart மட்டும் தேவை.

👉 Simple-ஆ சொன்னா:

--- created value use பண்ணணும் என்றால் அதை பெயர் வைத்துக் கொள்ளலாம்.
--- Use பண்ணவேண்டாம்னா _ வைச்சிடலாம்.

--- “இந்த user-க்கு ஒரு Cart இருந்தா எடுத்துக்கோ, இல்லனா database-ல புதிய Cart create பண்ணு”

1️⃣ CartItemSerializer vs CartSerializer

CartItemSerializer

--- Single cart item-ஐ represent pannum (like quantity, product).
--- Example: { "id": 1, "product": "Apple", "quantity": 3 }

CartSerializer

--- Whole cart-ஐ represent pannum, including all items inside it.

✅ Summary

--- CartItemSerializer → update pannum, validate pannum.
--- CartSerializer → response la whole cart data send pannum, so frontend-ku easy.
